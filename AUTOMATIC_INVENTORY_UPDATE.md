# Automatic Inventory Update System\n\n## Overview\n\nWhen a Purchase Order (PO) is confirmed, the system automatically:\n1. **Updates warehouse inventory** with received items\n2. **Creates a Goods Receipt Note (GRN)** automatically\n3. **Updates PO status** to 'received'\n4. **Logs all transactions** for audit trail\n\n## API Endpoints\n\n### 1. Confirm Purchase Order (Enhanced)\n```\nPOST /api/purchase-orders/{id}/confirm\n```\n\n**Description:** Confirms a purchase order and automatically updates inventory.\n\n**Response:**\n```json\n{\n  \"success\": true,\n  \"message\": \"Purchase order confirmed successfully. Inventory has been updated automatically.\",\n  \"data\": {\n    \"grnId\": \"uuid-grn-id\",\n    \"grnNumber\": \"AUTO-GRN-PO001-1234567890\",\n    \"itemsProcessed\": 5,\n    \"warehouseUpdated\": \"Main Warehouse\"\n  }\n}\n```\n\n### 2. Get Confirmation Summary\n```\nGET /api/purchase-orders/{id}/confirmation-summary\n```\n\n**Description:** Get details about what will happen when PO is confirmed.\n\n**Response:**\n```json\n{\n  \"success\": true,\n  \"data\": {\n    \"po\": {\n      \"id\": \"po-uuid\",\n      \"po_number\": \"PO001\",\n      \"vendor_name\": \"ABC Supplier\",\n      \"warehouse_id\": \"warehouse-uuid\",\n      \"status\": \"sent\"\n    },\n    \"lines\": [\n      {\n        \"item_id\": \"item-uuid\",\n        \"item_name\": \"Product A\",\n        \"sku\": \"SKU001\",\n        \"quantity_ordered\": 100,\n        \"unit_cost\": 10.50,\n        \"current_stock\": 50,\n        \"available_stock\": 45\n      }\n    ],\n    \"summary\": {\n      \"totalItems\": 5,\n      \"totalQuantity\": 500,\n      \"totalValue\": 5250.00,\n      \"warehouseName\": \"Main Warehouse\",\n      \"vendorName\": \"ABC Supplier\"\n    }\n  }\n}\n```\n\n### 3. Update PO Status (Enhanced)\n```\nPUT /api/purchase-orders/{id}/status\n```\n\n**Body:**\n```json\n{\n  \"status\": \"confirmed\"\n}\n```\n\n**Note:** When status is set to 'confirmed', it automatically triggers the inventory update process.\n\n## Automatic Process Flow\n\n### When PO is Confirmed:\n\n1. **Validation**\n   - Verify PO exists and is in valid status\n   - Check all line items are valid\n   - Validate warehouse access\n\n2. **GRN Creation**\n   - Auto-generate GRN number: `AUTO-GRN-{PO_NUMBER}-{TIMESTAMP}`\n   - Create GRN header with confirmation details\n   - Create GRN lines for each PO line item\n\n3. **Inventory Updates**\n   - For each line item:\n     - Add quantity to warehouse inventory\n     - Update inventory projections\n     - Record inventory event with cost information\n     - Update average cost calculations\n\n4. **Status Updates**\n   - Mark PO lines as 'received'\n   - Update PO status to 'received'\n   - Record audit trail\n\n5. **Logging**\n   - Log successful inventory updates\n   - Record GRN creation\n   - Audit trail for compliance\n\n## Database Changes\n\n### Tables Updated:\n- `purchase_orders` - Status updated to 'received'\n- `purchase_order_lines` - Quantity received and status updated\n- `goods_receipt_notes` - New GRN created\n- `grn_lines` - GRN line items created\n- `inventory_projections` - Stock levels updated\n- `inventory_events` - Movement history recorded\n\n## Error Handling\n\n### Common Errors:\n- **PO Not Found:** Returns 404 with appropriate message\n- **Invalid Status:** Cannot confirm already received POs\n- **Warehouse Access:** User must have access to target warehouse\n- **Database Errors:** All operations are wrapped in transactions\n\n### Transaction Safety:\n- All operations are performed within database transactions\n- If any step fails, entire process is rolled back\n- Ensures data consistency\n\n## Usage Examples\n\n### Frontend Integration:\n```javascript\n// Confirm PO and update inventory\nconst confirmPO = async (poId) => {\n  try {\n    const response = await fetch(`/api/purchase-orders/${poId}/confirm`, {\n      method: 'POST',\n      headers: { 'Content-Type': 'application/json' }\n    });\n    \n    const result = await response.json();\n    \n    if (result.success) {\n      console.log('PO confirmed:', result.data);\n      // Show success message with GRN details\n      alert(`Inventory updated! GRN: ${result.data.grnNumber}`);\n    }\n  } catch (error) {\n    console.error('Confirmation failed:', error);\n  }\n};\n```\n\n### Get Summary Before Confirmation:\n```javascript\n// Get confirmation summary\nconst getSummary = async (poId) => {\n  const response = await fetch(`/api/purchase-orders/${poId}/confirmation-summary`);\n  const data = await response.json();\n  \n  if (data.success) {\n    console.log('Items to receive:', data.data.lines.length);\n    console.log('Total value:', data.data.summary.totalValue);\n  }\n};\n```\n\n## Benefits\n\n1. **Automation:** No manual inventory entry required\n2. **Accuracy:** Eliminates human errors in stock updates\n3. **Audit Trail:** Complete tracking of all movements\n4. **Real-time Updates:** Inventory is immediately available\n5. **GRN Integration:** Automatic documentation creation\n6. **Cost Tracking:** Proper cost basis for inventory valuation\n\n## Configuration\n\n### Environment Variables:\n- Standard database connection settings\n- Logging level configuration\n- Transaction timeout settings\n\n### Permissions Required:\n- `purchase_management` - To confirm purchase orders\n- `purchase_view` - To view confirmation summaries\n- Warehouse access permissions for target warehouse
